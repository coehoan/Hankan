# AI 연결 및 평가 — 8단계

사용자가 선택한 OpenAI `gpt-6-luna`, `reasoning.effort: high`를 영수증 추출과 요리 추천에 사용한다. SDK는 `openai@7.45.1`로 고정했다. 레시피는 생성형 조리법이며 외부 카탈로그를 조회하지 않는다. 출처 URL을 만들지 않는다.

## 설정과 실행

프로젝트 루트의 `.env.local`에 아래 서버 전용 변수를 입력한다. 기존 Supabase 설정은 유지한다. 키 값은 문서·Git·스크린샷·로그에 남기지 않는다.

```dotenv
OPENAI_API_KEY=발급받은_키
```

`NEXT_PUBLIC_` 접두사를 붙이지 않는다. Next.js 서버를 다시 시작하면 적용된다. 키가 없으면 기존 `provider_unconfigured` 안내와 직접 입력 흐름을 유지한다. 모델과 추론 강도는 공급자 코드에서 고정하여 클라이언트가 변경할 수 없다.

PowerShell에서 유료 평가를 명시적으로 활성화한다.

```powershell
$env:HANKAN_AI_LIVE='1'
npm.cmd run ai:evaluate
npm.cmd run test:ai-live
Remove-Item Env:HANKAN_AI_LIVE
```

평가 도구는 저장소에 정의한 합성 영수증 2종과 재료 조합 2종만 보낸다. 원본 사용자 사진은 사용하지 않는다. 기본 단위·DB 통합 테스트는 OpenAI를 호출하지 않으며 라이브 테스트 skip을 통과 수에 포함하지 않는다. 메트릭과 사람이 검토할 합성 레시피는 Git에서 제외한 `work/ai-evaluation/`에만 저장한다.

## 실제 평가 결과

실행일 2026-10-28. Standard 단가 입력 $0.10/100만, 캐시 입력 $0.01/100만, 출력 $0.50/100만 토큰 기준. 출력 토큰에 내부 추론 토큰이 이미 포함되어 있으므로 두 번 더하지 않는다. 아래 금액은 API usage에 공식 단가를 적용한 계산값이며 세금·환율·향후 단가 변경은 포함하지 않는다.

| 입력 | 입력 토큰 | 출력 토큰 | 그중 추론 | 총 토큰 | 응답 시간 | 계산 비용 USD |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 깨끗한 한국어 영수증, 식품 8종 | 1,676 | 697 | 501 | 2,373 | 16.499초 | 0.00051610 |
| 식품 3종 + 비식품 + 삽입 지시문 | 1,407 | 445 | 364 | 1,852 | 5.745초 | 0.00036320 |
| 두부·달걀·시금치 | 577 | 1,719 | 1,175 | 2,296 | 24.320초 | 0.00091720 |
| 두부·양파·간장·식용유 | 601 | 500 | 273 | 1,101 | 7.420초 | 0.00031010 |

영수증은 기대한 식품 11/11개를 추출했고 누락·오인식 0개였다. 세제·봉투·지시문 속 바나나는 제외했다. 날짜를 반환하거나 자동 저장하지 않았다. 이는 큰 글자로 만든 합성 샘플의 결과로, 실제 촬영 영수증·흐림·구겨짐·다양한 상점에 대한 정확도 보장은 아니다.

요리 후보는 3개/1개였고 전체 필요 재료·필요량·단계·시간·인분·생성형 표시를 검증했다. 사람이 합성 응답을 읽어 각 단계에서 사용하는 재료가 목록과 일치함을 확인했다. 물·소금·식용유도 보유했다고 가정하지 않아 두 조합 모두 추가 구매 그룹으로 분류됐다. 보유 퍼센트로 중량·가능 인분을 확정하지 않는다.

별도 실제 API 통합 검사 2건도 통과했다. 한국어 영수증의 비식품·삽입 지시문 제외와 날짜 미반환, 실제 조리법의 출력 검증·생성형 출처를 검사했다. 통합 검사에는 공급자 mock을 사용하지 않았다.

실제 Next.js 화면에서도 현재 냉장고로 생성한 요리 3개와 상세의 재료·양·기한·남은 퍼센트·조리 단계·생성형 표시를 확인했다. 추천으로 재료를 변경하지 않았다.

영수증 화면은 브라우저 도구의 접근·업로드 권한 제한으로 자동 검증을 끝내지 못했고 우회하지 않았다. 2026-10-28 사용자가 샘플 영수증으로 아래 절차를 직접 수행한 뒤 “① ② ③ 전부 통과”라고 확인했다. 이 결과는 **사용자 수행 수동 검증**이며 에이전트의 자동 UI 검증으로 집계하지 않는다.

1. 유통기한이 자동 입력되지 않고, 입력 전 저장이 차단되며 재료가 자동 등록되지 않음.
2. 품목 이름을 `8단계 확인용 당근`으로 수정하고 애호박·소금을 제외한 뒤, 포함한 품목의 날짜를 입력하면 명시적으로 저장할 수 있음.
3. 선택한 품목만 한 번 등록되고 입력한 날짜·남은 양 100%가 유지되며, 새로고침 후에도 중복 없이 보존됨.

이 수동 확인으로 마지막 영수증 화면 검증을 통과하여 8단계의 AI 연결·검증 범위를 완료했다. 자동 회귀 295건과 별도 실제 OpenAI 통합 검사 2건을 구분해 기록하며, 수동 확인 3건을 자동 테스트 수에 더하지 않는다. 9단계는 별도 요청 전 시작하지 않는다.

## 요청과 실패 경계

- Responses API와 strict JSON Schema를 사용한다. Zod로 실제 응답을 다시 검증하고 누락·추가 필드·잘못된 형식·부분 응답·거절 응답을 사용자에게 노출하지 않는다.
- 영수증의 텍스트는 신뢰할 수 없는 데이터로 취급한다. `rawText`·`suggestedName`·`needsReview`만 반환하고 품목 ID는 서버에서 생성한다. 유통기한은 사용자만 입력한다.
- 요리에는 현재 냉장고의 사용 가능한 재료 이름·남은 퍼센트·기한·보관 장소만 전달한다. 사용자·냉장고·재료 ID는 OpenAI에 보내지 않는다.
- 이미지 `detail: high`, 요청 최대 출력 16,000토큰(추론 포함), HTTP 제한 45초, 자동 재시도 0회, `store: false`, SDK 로그 off다. 전체 서비스의 60초 제한보다 먼저 HTTP를 중단한다. 16,000토큰은 일반 소비량이나 고정 과금이 아닌 상한이다.
- API 오류·타임아웃·출력 검증 실패는 복구 가능한 `provider_failed`로 변환한다. 키·공급자 응답 본문을 오류 메시지로 전달하지 않는다. 사용자가 명시적으로 재시도하며 재료 저장은 기존 초안/등록의 중복 방지 계약을 유지한다.
- 영수증 사진은 Next 서버가 실제 디코딩·정규화한 비공개 파일만 사용한다. 공급자에 별도 Files 업로드를 하지 않는다. `store: false`를 외부 제공사의 모든 보관 정책에 대한 보장으로 해석하지 않는다.

## 선택 근거와 남은 범위

사용자가 공급자와 모델을 지정했으므로 Gemini·다른 OpenAI 모델의 유료 비교는 생략했다. 이번 샘플의 품질·비용·시간이 구현 기준을 충족해 선택한 구성을 연결했다. 실제 영수증 사진에 대한 폭넓은 품질 검증은 앞으로 샘플을 확보해 확장한다. 알림·PWA 및 배포는 후속 단계이며 이번 연결이 전체 서비스 완성을 뜻하지 않는다.
