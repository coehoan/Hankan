# UX 검토 우선순위 8개 개선

**Goal:** 채팅의 읽기 전용 검토 보고서 D 항목을 현재 미커밋 작업 위에 반영한다.
**Architecture:** 기존 Dialog·API·권한·테마를 재사용한다. DB 스키마와 데이터는 바꾸지 않는다.
**Tech Stack:** Next.js 16.4.3 / React / TypeScript / Vitest.
**Spec:** 2026-11-12 현재 채팅의 보고서 B·C·D 및 사용자의 수정 승인.

## 제약·검토 초점
- 기존 환경·데이터·미커밋 변경 보존. push·배포·커밋 없음.
- 파괴적 요청은 확인 전 전송하지 않고 취소·실패 시 입력과 초점을 보존한다.
- 영수증 오류는 포함된 품목에만 적용하며 문자 수는 Unicode 코드포인트 기준이다.
- 재료 재조회와 추천 상태 재조회는 구분한다.
- 알림 계정 설정과 기기 권한·구독 확인을 구분하고 권한 요청은 사용자 동작에서만 한다.
- 공통 404는 중립적이고 추천 상세는 대상별 안내를 제공한다.

## 구현·검증
- [x] 1. inventory-screen·review-screen: 삭제/초안 취소 확인. 기존 회귀 테스트를 먼저 실패시킨 뒤 구현·취소/실패/중복 요청 검사.
- [x] 2. review-screen: 품목별 이름·날짜 오류와 요약/이동, 80자 검증 일치. 제외된 행·81자·날짜 누락 테스트.
- [x] 3. recipe-list/results: 재료 다시 불러오기 연결. HTTP 경계 회귀 검사.
- [x] 4. recipe-results: 결과 없는 분류 숨김. 부분 결과·전부 0개 상태 유지.
- [x] 5. notification settings: 읽기 전용 기기 상태 확인, 필요한 경우 연결 버튼. 기존 즉시 저장·자동 연결 보존.
- [x] 6. saved recipe/global404: 대상별 오류와 중립적 오류 문구.
- [x] 7. receipt upload: 선택과 업로드/분석의 버튼·안내 구분.
- [x] 8. ingredient/sharing/settings: 내부 용어·상시 안내·삭제 범위 표현 정리.
- [x] 관련·전체 단위 검사, 타입·변경 파일 포맷/린트, 로컬 실제 화면 확인과 자동 테스트의 합성 오류 상태 검증, 변경 검토.
- [x] 최종 보고: 영향 범위 큰 변경과 실제 미검증 영역의 확인 방법을 구분.


## 검증 기록
- 관련 테스트 80개 통과. 삭제 충돌 복구는 추가 테스트를 먼저 실패시킨 뒤 수정하고 해당 테스트 통과를 확인했다.
- 독립 검토 Important 1건: 확인 창의 오래된 재료 버전으로 삭제 재시도가 반복 실패함. Final: fixed — requires fresh confirmation after a delete version conflict RED→GREEN. 충돌 후 창을 닫고 최신 내용을 다시 확인한다.
- 실제 Chrome: 데스크톱/390px에서 삭제 확인과 취소·초점 복귀, 영수증 선택/분석 안내, 기존 추천의 빈 분류 숨김, 현재 기기 연결 정상 표시, 추천 전용/일반 404 안내 확인. 기존 데이터 변경 없이 진행했다.
- 영수증 오류/초안 취소·재조회 실패 회복·알림 권한 분기는 합성 응답 단위/컴포넌트 검사이며 실제 AI/OCR·실기기 푸시 수신 판정이 아니다.
- DB·worker·배포 설정 변경 없음. DB 통합/제품 빌드/AI 유료 호출/배포는 이번 검증에서 실행하지 않았다.
- 최종 검증: 단위·컴포넌트 55파일/507개 통과, 타입·변경 파일 포맷 통과, 변경 파일 린트 오류 0(기존 영수증 미리보기 img 경고 1), git diff --check 통과. 리뷰 보류·판단 예외 없음.

## 후속 릴리스 승인 (2026-11-12)
- 사용자가 현재 변경의 커밋·dev push·운영 배포를 승인했다. 앞선 미실행 기록은 UX 구현 단계 기준이다.
- 배포 전 로컬 DB 통합의 기존 테스트 푸시 사례가 개발 전용 API 변경을 반영하지 않아 실패했다. 개발 모드를 명시하고 운영·test 모드 차단 사례를 추가한 뒤 137개 통과·실 API 2개 스킵을 확인했다. pgTAP 125개, 배포 보호 59개, 전체 포맷·worker 빌드도 통과했다.
- 환경파일·next-env.d.ts·work 산출물은 보존하고 커밋에서 제외한다. 기존 GitHub Actions의 검사→운영 빌드→미적용 migration 확인/적용→Vercel 배포 순서를 유지한다.
