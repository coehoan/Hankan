# 식재료 목록 Realtime 전환

사용자 승인 범위: 3초 주기 조회를 제거하고 Supabase Realtime 변경 알림으로 갱신한다. 배포와 클라우드 DB 변경은 하지 않는다.

- 냉장고별 private Broadcast 채널 `fridge:<uuid>:inventory`, 이벤트 `inventory_changed`를 사용한다.
- ingredients INSERT/UPDATE/DELETE 및 fridge_members 변경 시 DB 트리거가 빈 payload의 변경 신호만 전송한다. 재료·회원 상세값은 보내지 않는다.
- realtime.messages SELECT 정책은 현재 냉장고 멤버에게만 구독을 허용한다. 클라이언트 발행은 허용하지 않는다. 멤버십 권한은 JWT 사용자 ID로 검사한다.
- 클라이언트는 첫 진입, 구독 완료/재연결, 화면 복귀/온라인 복귀, 변경 신호, 본인 저장 후에 기존 GET API를 통해 목록을 재검증한다. 주기적인 목록 조회는 없다.
- 연속 신호는 짧게 병합한다. 조회나 저장 중 수신한 신호를 버리지 않고 완료 후 재조회한다. 이전 냉장고의 콜백과 응답은 무시한다.
- 숨겨진 탭·오프라인·로그아웃·접근 권한 상실·unmount에서 구독과 타이머를 정리한다. 복귀 때 구독하고 목록을 다시 확인한다.
- 연결 실패 시 주기 조회로 되돌아가지 않는다. 연결 상태 안내와 수동 새로고침을 제공하고 SDK의 재접속을 사용한다.
- 기존 낙관적 업데이트, version 충돌 처리, HTTP 권한 검사, 입력 보존을 유지한다.
- 정책은 구독 시 계산되어 캐시되므로 제외된 멤버가 변경 신호를 잠시 받을 수 있다. 신호에 상세값을 넣지 않으며 멤버십 변경 신호 및 GET API의 현재 권한 검사로 목록을 지운다.

검증: 사용자 훅 회귀 테스트, DB 정책/트리거 검사, 실제 로컬 Realtime에서 소유자·멤버·비회원 및 생성·수정·삭제·제외·재구독 통합 검사. 키·토큰은 기록하지 않는다.
