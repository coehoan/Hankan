# 한칸 아이디 인증 변경

사용자가 승인한 방향: 이메일 인증·이메일 입력·메일 재설정을 제거하고 일반 아이디/비밀번호로 가입한다. 비밀번호 변경은 로그인한 본인만 새 비밀번호 두 번으로 수행한다. 분실은 관리자가 초기화한다.

Supabase Auth와 현재 UUID·냉장고/RLS 구조를 유지한다. 아이디는 구현자 기본값으로 영문/숫자/밑줄 4~24자, 대소문자 구분 없이 소문자로 정규화한다. 서버에서만 `<아이디>@accounts.hankan.invalid` 인증 식별자로 매핑하고 실제 주소를 수집하거나 메일을 발송하지 않는다. 기본 공개 가입 API와 Supabase의 비밀번호 처리를 사용한다. 서버 관리자 키로 공개 가입 제한을 우회하지 않는다. 현재 클라우드 계정은 0개다.

가입 성공 시 세션을 확인한 뒤 원래 내부 목적지로 바로 이동한다. 로그인 폼에 관리자 초기화 안내를 표시하고, 로그인 후 접근하는 비밀번호 변경 화면에는 새 비밀번호·확인 두 칸을 둔다. 확인 일치는 서버에서도 검사한다. 이메일 재설정 API와 callback을 제거하고 오래된 재설정 URL은 로그인/변경 화면으로 안전하게 안내한다.

관리자는 서버 전용 CLI에서 대상 아이디와 새 비밀번호 두 번을 입력한다. 비밀번호를 명령행 인자·로그·파일에 남기지 않는다. 관리자 키는 서버 환경에서만 읽고 해당 계정만 변경한다. 변경 후 새 비밀번호로 얻은 임시 세션을 이용해 전역 로그아웃을 요청한다. 기존 JWT의 만료까지의 유효성은 Supabase의 표준 모델을 따른다.

Supabase Confirm email을 끄고 로컬 config에도 같은 설정을 적용한다. 기존 로컬 데이터는 보존한다. 브라우저 정책이 설정 저장 시 별도 확인을 요구하면 구현·검증을 끝낸 뒤 구체적인 변경에 대해서만 확인한다. 인증 보안 요구는 이메일 소유 확인 대신 비밀번호와 현재 로그인 세션, 관리자 서버 권한으로 제한한다.
