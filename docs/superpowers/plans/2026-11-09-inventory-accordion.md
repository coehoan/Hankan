# 식재료 목록 아코디언 구현 계획

> **For agentic workers:** Use superpowers:executing-plans and superpowers:test-driven-development. Run the steps in order.

**목표** 각 기한 구역을 독립적으로 열고, 필요한 만큼 더 보고, 검색을 지웠을 때 기존 목록으로 돌아간다.

**구조** `InventoryScreen`은 전체 조회 결과를 필터링한 뒤 기한별로 묶는다. 일반 목록과 검색의 화면 상태를 분리하고, 구역 내부에서 카드 개수와 키보드 포커스를 제어한다.

**기술** Next.js App Router, React, CSS, Vitest, Testing Library.

**설계** [식재료 목록의 아코디언과 더 보기](../specs/2026-11-09-inventory-accordion-design.md)

## 범위

한 번에 5개씩 표시한다. 냉장고별 조회·수정 API, 기한 판정, 추천 데이터, 요약 수치는 기존대로 사용한다. 변경은 현재 작업 폴더에 남긴다.

## 구현과 확인

- [x] 기존 목록, 냉장고 전환 시 컴포넌트 키, A1 스타일, 테스트 환경을 확인한다.
- [x] 기존 목록 컴포넌트 테스트에서 기본 펼침, 구역별 5개 단위, 총개수, 마지막 더 보기 제거와 추가된 행의 포커스를 확인한다.
- [x] 이름과 위치의 교집합, 정규화된 같은 검색어, 검색 중 빈 구역이 다시 채워지는 경우, 검색 종료 후 복원을 확인한다.
- [x] 새 테스트가 실패하는 이유가 기능 부재인지 확인한다.
- [x] `InventoryScreen`에서 필터 결과를 그룹화하고 일반 상태와 검색 상태를 관리한다. 검색 조건이 바뀌면 검색 상태를 기본값으로 되돌린다.
- [x] 구역의 제목을 실제 버튼으로 만들고 제어 영역과 연결한다. 카드는 PC 두 열과 모바일 한 열로 유지하고 더 보기를 누른 뒤 첫 추가 행으로 포커스를 옮긴다. 수정한 행이 표시 범위 밖으로 이동하면 구역 제목으로 포커스를 돌려준다.
- [x] 구조 문서에 목록 동작을 기록하고 컴포넌트 테스트, 관련 셸 테스트, 타입·린트·포맷을 확인한다.
