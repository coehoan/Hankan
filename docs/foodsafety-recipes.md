# 식약처 레시피 DB

로컬 서버는 `.env.local`의 `FOODSAFETY_API_KEY`를 사용한다. `NEXT_PUBLIC_` 접두사는 붙이지 않는다. AI 요리 추천과 영수증 분석은 기존 `OPENAI_API_KEY`를 사용한다.

향후 사용자가 배포할 때는 Vercel 프로젝트 → Settings → Environment Variables에서 `FOODSAFETY_API_KEY`를 **Production** 환경에 추가해야 한다. 로컬 환경파일은 업로드하지 않는다. GitHub Actions의 배포 빌드는 기존 Vercel 환경변수 가져오기 절차를 사용한다. 이번 변경에는 DB 마이그레이션이 없다.

추천 버튼 한 번으로 AI 추천과 식품안전나라 COOKRCP01 레시피를 동시에 받아 한 목록으로 보여준다. AI는 새 작업을 접수할 때 호출하며(진행 중 작업·중복 요청은 재사용), 식약처 목록은 아래 캐시를 재사용한다. 첫 요청에서 전체 목록을 1,000건씩 읽고 완전한 카탈로그만 24시간 캐시한다. 같은 서버의 동시 요청은 하나로 합치고, 서버 인스턴스 간에는 Next Data Cache를 사용한다. 24시간 이후에는 Next의 재검증 시점까지 직전 캐시가 사용될 수 있다. 각 공급자는 결과와 출처 유형을 독립 검증하고 50초 안에 응답해야 한다. 한쪽의 오류·제한·시간 초과는 다른 쪽의 정상 결과를 버리지 않는다. 둘 다 실패하면 안전한 재시도 오류를 표시한다. 정상 응답이 빈 목록이면 추천 없음으로 처리한다. 키 변경 시 캐시 공간도 달라진다.

기한이 지나지 않고 남은 양이 있는 재료를 비교한다. 달걀/계란과 제한된 손질 표현을 정규화하고, 보유 재료만 쓰는 요리 → 임박 재료 활용 → 부족한 재료 수 순서로 분류한다. 식약처 최대 12개와 AI 결과를 합치되 공백·대소문자 등을 정규화한 요리명이 같으면 식약처 원본 하나를 남긴다. 서로 다른 요리의 재료나 순서를 섞지 않는다. 소금·물·기름도 등록되어 있지 않으면 추가 재료로 분류한다. 재료 문장은 자유 형식이므로 비교 결과와 함께 원문을 확인해야 하며, 보유 퍼센트로 중량이나 조리 가능한 인분을 보장하지 않는다.

요리명, 재료 원문, 순서, 출처와 `RCP_SEQ`를 보존한다. 재료/조리법이 비어 있거나 유효한 레코드로 읽을 수 없는 항목은 제외한다. 괄호가 맞지 않거나 쉼표 없이 여러 재료·분량이 이어지는 등 파싱이 모호한 원문도 제외하여 재료 누락으로 조리 가능하다고 표시하지 않는다. 원본이 제공하지 않는 시간·인분은 추정하지 않는다. 출처·레코드 ID는 서버 검증용으로 유지하며 목록과 상세에는 출처·AI 표식을 표시하지 않는다.

제공 API: [식품안전나라 COOKRCP01](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=COOKRCP01).

비동기 접수·부분 결과·추천 내역·완료 알림은 [비동기 추천 안내](async-recipes.md)를 따른다. 독립 worker에서는 Next 요청 캐시 대신 프로세스 내 카탈로그 캐시를 사용한다.
