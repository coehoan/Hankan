# 구조·핵심 동작

## 코드 찾기

| 경로 | 역할 |
| --- | --- |
| `src/app/(app)` / `(auth)` | 인증된 화면 / 로그인·가입 화면 |
| `src/app/api` | HTTP 경계: 입력·origin·인증 검사, 서비스 호출 |
| `src/features/shell` | 브랜드·프로필 메뉴, 냉장고 선택, 마이페이지·냉장고 관리 |
| `src/features/inventory` | 재료 도메인·서비스·목록·입력·남은 양·동기화 |
| `src/features/auth` | 일반 아이디 인증, 비밀번호 변경·관리자 초기화 |
| `src/features/sharing` | 초대·수락·취소·내역 정리·멤버 관리 |
| `src/features/receipts` / `ai` | 사진 업로드·검토·저장·정리 / 서버 AI 공급자·응답 검증 |

| `tests/integration` / `tests/support` | 로컬 DB 통합 검사 / 격리된 테스트 계정·공급자 fixture |

## 유지해야 할 동작

목록은 기한 지남과 임박 구역을 기본으로 펼치고 여유 구역은 접는다. 각 구역의 전체 개수를 표시하며 더 보기로 카드를 5개씩 추가한다. 이름과 위치는 조회한 전체 재료에 적용한다. 이름 검색은 결과 구역을 열며, 검색을 지우면 일반 목록의 펼침과 표시 개수를 복원한다.

- **화면:** 상단 주 메뉴에서 식재료·요리 추천·추천 내역을 오간다. 식재료 화면은 현재 냉장고와 기한별 건수, 직접 등록·영수증 등록을 먼저 보여준다. 검색과 보관 위치 필터 아래에서 기한별 그룹을 펼치고, 요리 추천 화면에서는 조리 시간·인분·추가할 재료를 비교한 뒤 조리법을 연다. 냉장고 전환과 계정 메뉴는 기존 키보드 동작과 권한 검증을 유지한다.
- **스타일:** `src/app/design-system.css`는 따뜻한 종이색 배경, 짙은 녹색, 로컬 Pretendard와 공통 컨트롤을 정의한다. `src/app/workspace.css`는 화면 배치와 좁은 화면의 재배치를 담당한다. 구분선으로 재료와 추천을 나누고, 강조 면은 냉장고 요약과 주요 작업에 사용한다. 라이트·다크·시스템 테마는 같은 정보 구조를 사용한다.
- **재료:** 직접 입력 또는 영수증 등록을 선택한다. 유통기한은 필수, 남은 양은 0~100의 5단위. 같은 재료도 구매 묶음별로 관리하고 직접 삭제한다. 수정·삭제는 `expectedVersion`, 새 등록은 재시도에도 같은 `requestId`를 사용한다.
- **목록:** 3초 폴링 없이 냉장고별 Supabase private Broadcast(`fridge:<uuid>:inventory`, `inventory_changed`)로 변경을 감지한다. 신호는 상세값 없이 전송하며 기존 GET API로 권한과 목록을 재검증한다. 150ms 동안 신호를 병합하고 진행 중 조회·저장 이후에도 변경을 반영한다. 첫 진입·구독 완료/재연결·포커스/온라인 복귀·저장 후 재조회한다. 숨김·오프라인·전환·종료 시 구독을 정리하고 이전 콜백·응답을 무시한다. 멤버십 변경이나 로그아웃으로 권한을 잃으면 목록을 지운다. 연결 실패 시 안내와 수동 새로고침을 제공하며 폴링으로 복귀하지 않는다. 수정 충돌은 입력을 보존한다. 성공 알림은 닫기 가능하며 마지막 표시부터 3초 뒤 닫힌다.
- **공유:** 모든 현재 멤버가 재료와 냉장고 이름을 수정한다. 초대·내보내기는 소유자 전용. 새 초대는 24시간·1회 사용이며 원문 대신 해시만 저장한다. 기존 발급 링크의 만료 시각은 유지한다. 내역 정리는 만료·취소·사용 완료만 삭제하고 활성 링크·멤버십을 보존한다.
- **관리:** 알림·북마크로 연 냉장고도 관리 화면에 그대로 전달한다. `/fridges/manage?fridgeId=...`는 서버가 접근 가능한 목록으로 검증한다.
- **영수증:** 사진 선택 → 미리보기 → 품목 확인(업로드 후 AI 자동 분석) → 결과 확인·수정 → 유통기한 직접 선택 → 명시적 저장. 분석 실패 시 기존 사진으로 재시도하거나 직접 입력한다. AI 결과를 바로 재료로 저장하지 않는다. 사진·초안은 업로더 전용이며 저장·취소 후 원본과 staging 파일을 정리한다.
- **추천:** 서버 전용 `FOODSAFETY_API_KEY`로 식약처 COOKRCP01 카탈로그를 조회한다. 1,000건씩 완전 조회 후 24시간 Next Data Cache에 저장하며 실패·부분 응답은 정상 캐시하지 않는다. 외부로 계정·냉장고·재료 정보를 보내지 않는다. 현재 사용 가능한 재료 종류와 임박 기한으로 분류·정렬하고 최대 12개를 반환한다. 추천 버튼은 AI 레시피도 동시에 요청하고 두 결과를 독립 검증한 뒤 한 목록에 합친다. 각 경로 50초 제한이며 한쪽 실패 시 다른 정상 결과를 사용한다. 같은 정규화 요리명은 식약처 원본 하나를 유지한다. 출처·레코드 ID·원본 재료 문장·조리법을 보존하며 미제공 시간·인분은 null로 표시한다. 자유 형식 재료 분리는 보수적으로 하며 재료 종류 일치가 실제 수량·대체 가능성을 보장하지 않는다. 추천은 서버 스냅샷을 저장하고 HTTP 202로 즉시 접수한다. 공급자 결과는 각각 저장하며 화면 이탈 후에도 Next after와 기존 worker가 이어서 처리한다. 내역은 요청자이면서 현재 멤버인 사용자만 조회한다. 재료·남은 양은 바꾸지 않고 현재 재료·날짜와 다르면 추천 당시 기준임을 표시한다. 완료 푸시는 기존 알림 설정을 따르며 전송 직전 권한을 재확인한다. 자세한 복구·운영 기준은 docs/async-recipes.md를 따른다. 기존 AI 프롬프트와 최소 재료 입력 정책을 유지하며 출처·AI 표시는 목록과 상세에서 숨긴다.
- **재료 일러스트:** `public/illustrations`의 자체 제작 SVG 108종(재료 계열 107종 + 기본 용기)을 사용한다. 부드러운 곡선·이어지는 색 변화·둥근 외곽선, 96×96 좌표계·투명 배경을 유지하며 목록에서는 72px로 표시한다. `ingredient-art-catalog.ts`에서 이름·별칭을 관리하고 `ingredient-art.tsx`가 표시한다. 정확한 별칭 → 가장 긴 부분 일치 → 수식어·수량을 제거한 한 글자 이름 순으로 연결하며, `감자전분`·`김치만두`·`멸치액젓` 등 구체적인 재료를 우선한다. 모르는 이름은 기본 용기를 쓴다. `파`·`알`의 무분별한 부분 일치는 금지한다. 범위·추가 방법은 [일러스트 안내](../docs/ingredient-illustrations.md)를 참고한다.
- **계정:** 일반 아이디·비밀번호, 이메일 인증 없음. 새 비밀번호 두 번으로 변경하고 분실은 관리자 초기화. 표시명·사용자 메타데이터를 권한 판정에 사용하지 않는다.
- **알림:** OFF는 즉시 저장하고 실패 시 이전 상태로 복구한다. ON은 시간 설정 후 별도 저장한다. 마이페이지의 테스트 버튼은 저장된 알림 설정이 켜져 있을 때 현재 기기의 알림 권한과 구독을 확인한다. 서버는 로그인 계정과 기기의 구독을 확인한 뒤 해당 기기에만 웹 푸시를 보낸다. 서비스 워커는 테스트 알림을 표시하고 탭하면 마이페이지 알림 설정을 연다. 발송 성공과 실제 기기 수신은 별개다.

API 변경은 기존 contracts/service/http 패턴을 따른다. 서버의 현재 멤버십 검사, 브라우저 JSON 변경 요청의 동일 origin 검사, private/no-store 응답을 유지한다. 사진 multipart와 서버 전용 worker는 각각의 기존 입력·인증 계약을 따른다. 테마와 공통 Dialog의 키보드·포커스 처리도 보존한다.
