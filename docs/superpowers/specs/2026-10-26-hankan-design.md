# 식재료 관리 서비스 설계 초안

작성일: 2026년 10월 26일
서비스명: 한칸은 가칭이며 최종 이름은 미정
상태: 2026년 10월 26일 사용자 승인 완료. 공동 관리와 개인별 알림 시간 설정을 포함한다.

이 서비스는 사용자가 보유한 식재료와 각 재료의 유통기한을 한곳에서 확인하고, 먼저 소비해야 할 재료로 요리를 찾도록 돕는다. 특히 1인 가구가 구매한 재료를 잊거나 사용할 시기를 놓쳐 버리는 일을 줄이는 것이 목적이다. 웹으로 제공하고 휴대폰 홈 화면에 설치할 수 있는 PWA를 지원한다.

## 사용자와 확정된 요구사항

- 여러 사용자가 가입하고 각자 자신의 냉장고와 식재료 목록을 관리한다.
- 다른 사람을 초대해 같은 냉장고의 식재료를 공동 관리한다. 초대한 사람도 재료 추가·수정·남은 양 변경·삭제를 할 수 있다.
- 재료를 직접 입력하거나 영수증 사진의 AI 분석 결과로 등록한다.
- 영수증 분석 결과는 초안이다. 사용자가 품목을 확인하고 수정한 뒤 저장해야 목록에 반영된다.
- 사진으로 등록할 때도 유통기한은 사용자가 직접 입력한다.
- 재료의 남은 양을 퍼센트로 조절하고, 다 먹은 재료는 사용자가 삭제한다.
- 기한이 임박한 재료는 목록 상단에서 남은 일수와 함께 확인한다.
- 보유 재료로 만들 수 있는 요리와 추가 재료를 구매하면 만들 수 있는 요리를 모두 제공한다.
- 요리별 필요한 재료와 조리법을 확인한다.
- 지원하는 환경에서 사용자 동의를 받아 PWA 푸시 알림을 제공한다.
- 알림을 받을 시간을 사용자 본인이 지정할 수 있다.
- Next.js와 TypeScript, Supabase를 사용한다. AI API 제공사는 지금 확정하지 않는다.
- 확인한 화면 구성과 사용 흐름을 사용하고, 듀 민트의 라이트·다크 디자인을 적용한다.

## 서비스의 우선순위

첫째는 냉장고 상태를 빠르게 파악하는 것이다. 목록을 여는 것만으로 어떤 재료가 남았고 무엇을 먼저 써야 하는지 알 수 있어야 한다. 둘째는 기록을 쉽게 갱신하는 것이다. 재료 등록과 남은 양 변경, 삭제가 번거로워 실제 냉장고와 목록이 달라지면 서비스의 목적을 달성하지 못한다. 요리 추천은 이 두 가지를 이어 주는 기능이며 기한이 가까운 재료의 활용을 우선한다.

다음 행동은 피한다.

- AI가 읽은 품목이나 추정한 유통기한을 확인 없이 저장하는 행동
- 요리를 조회했다는 이유로 재료를 차감하는 행동
- 남은 퍼센트만으로 정확한 중량이나 가능한 인분을 보장하는 표현
- 기한이 지났다는 이유로 재료를 자동 삭제하는 행동
- 공유하지 않은 냉장고의 재료 정보를 섞어 조회하거나 추천에 사용하는 행동

## 검토한 구현 방식과 선택

| 방식 | 이 서비스에서의 장점 | 고려할 점 | 결정 |
| --- | --- | --- | --- |
| Next.js와 Supabase | 웹 화면과 서버 기능을 같은 프로젝트에서 관리하고, 사용자·공유 냉장고·멤버·재료 묶음을 PostgreSQL로 연결할 수 있다. 인증과 비공개 파일 저장도 함께 구성한다. | 냉장고 멤버십에 따른 데이터 접근 정책과 서버 권한을 명시적으로 설계해야 한다. | 사용자가 선택 |
| Next.js와 Firebase | 인증, 문서형 DB, 파일 저장을 이용해 웹 서비스를 구성할 수 있다. | 재료와 구매 묶음, 추천 데이터의 관계와 조회 방식이 달라진다. | 대안으로 검토 후 제외 |

AI 후보는 이미지 입력과 구조화된 결과를 지원하는 OpenAI API와 Gemini API, 영수증 전용 OCR과 생성형 AI를 조합하는 방식이다. 제공사 선택은 유예하되 실제 API 연결은 서비스 완성 조건에 포함한다. 연동 전에는 공급자를 교체할 수 있는 공통 입력·출력 형식으로 화면과 서버를 구성한다. 시안이나 개발용 예시 결과는 실제 AI 결과와 구분한다.

## 화면과 사용 흐름

### 가입과 로그인

첫 방문에서는 서비스 목적과 로그인 진입점을 제공한다. 가입 시 본인 소유 냉장고와 소유자 멤버십을 함께 만든다. 로그인 후에는 마지막으로 선택했던 접근 가능한 냉장고로 이동하고, 해당 권한이 없어졌다면 본인 냉장고로 돌아간다. 데이터가 없으면 재료 직접 입력과 영수증 등록을 안내한다. 로그인하지 않은 사용자는 냉장고 목록이나 영수증에 접근할 수 없다.

### 냉장고 공유와 초대

공유 방식은 멤버들이 동일한 냉장고 데이터에 접근하는 방식이다. 초대할 때 식재료 사본을 만드는 방식은 한 사람의 변경이 다른 사람에게 반영되지 않아 공동 관리 목적에 맞지 않으므로 사용하지 않는다.

냉장고 이름에서 본인 소유 목록과 참여 중인 공유 목록을 전환한다. 새 재료 등록, 영수증 저장, 요리 추천은 현재 선택한 냉장고에만 적용한다. 서로 다른 냉장고의 재료는 자동으로 합치지 않는다. 공유하지 않은 본인의 재료와 기존 구매 묶음은 그대로 유지한다.

| 동작 | 소유자 | 초대받은 멤버 |
| --- | --- | --- |
| 재료 조회·추가·수정·남은 양 변경·삭제 | 가능 | 가능 |
| 현재 냉장고 재료로 요리 추천 | 가능 | 가능 |
| 본인의 영수증으로 현재 냉장고에 등록 | 가능 | 가능 |
| 초대 링크 생성·취소와 멤버 내보내기 | 가능 | 불가 |
| 냉장고 나가기 | 소유자는 나갈 수 없음 | 가능 |
| 다른 멤버의 알림 시간·테마·영수증 초안 열람 | 불가 | 불가 |

1. 소유자는 멤버 관리에서 ‘초대 링크 만들기’를 누르고 링크를 복사해 원하는 사람에게 전달한다.
2. 초대받은 사람은 로그인 또는 가입 후, 냉장고 이름과 공동 편집 권한을 확인한다. 링크를 열기만 해서는 참여되지 않는다.
3. ‘이 냉장고에 참여’를 누르면 같은 재료 목록을 함께 관리한다. 기존 멤버가 다시 열면 중복 가입하지 않는다.
4. 링크는 7일 후 만료되며, 한 사람이 참여하면 사용 완료된다. 여러 명을 초대하려면 각각 새 링크를 만든다. 소유자는 사용 전 취소할 수 있다.
5. 만료·취소·사용된 링크는 가입을 진행하지 않고 새 초대가 필요함을 안내한다. 소유자는 자신을 다시 초대할 수 없다.
6. 멤버가 나가거나 소유자가 내보내면 그 냉장고에 대한 조회·수정·추천·구독 권한을 회수한다. 멤버가 이전에 등록한 재료는 냉장고에 남긴다.

멤버의 재료 변경은 다른 멤버가 열어 둔 목록에도 반영한다. 연결이 끊겼다가 돌아오면 현재 상태를 다시 읽는다. 같은 묶음에 대한 동시 수정은 버전을 비교하여 오래된 값으로 덮어쓰지 않고, 최신 값을 보여주며 다시 수정하도록 한다. 이미 삭제된 재료를 다른 멤버의 지연된 수정 요청으로 복원하지 않는다.

소유권 이전과 냉장고 자체 삭제는 첫 범위에서 제외한다. 소유자는 공동 냉장고를 유지하면서 멤버를 관리한다. 첫 범위에서는 소유자·멤버 두 역할만 제공하며 보기 전용 초대는 추가하지 않는다.

### 내 냉장고

첫 화면에는 선택한 냉장고의 이름과 전환 메뉴, 멤버 관리 진입점, 재료 목록과 등록 버튼을 둔다. 소유자에게는 초대 동작을 제공하며, 일반 멤버에게는 참여 중임을 표시한다. 보관 장소 필터와 이름 검색을 제공한다. 기한이 지난 재료는 ‘기한 지남’으로 구분하여 최상단에 남기고, 이후 임박한 재료와 여유 있는 재료를 기한이 가까운 순서로 보여준다. 같은 날짜는 등록 시각으로 정렬한다. 날짜와 상태를 함께 표시해 색상에만 의존하지 않는다.

각 재료는 이름, 보관 장소, 유통기한, 남은 양, 삭제 동작을 갖는다. 행을 누르면 이름·보관 장소·기한을 수정할 수 있다. 슬라이더는 값을 변경한 뒤 서버에 저장하고 저장 중·실패 상태를 표시한다. 저장 실패 시 마지막 저장값으로 복원하고 재시도할 수 있게 한다. 삭제는 해당 구매 묶음에만 적용하며 다른 묶음에는 영향을 주지 않는다.

웹의 넓은 화면에서는 임박 재료를 활용하는 추천 영역을 목록 옆에 둔다. 좁은 화면에서는 목록 뒤로 배치한다. 요리 추천 메뉴를 통해서도 같은 기능에 진입할 수 있다.

### 직접 입력

재료 이름과 유통기한, 보관 장소를 입력한 뒤 저장한다. 이름의 앞뒤 공백은 제거하며 빈 이름과 유효하지 않은 날짜는 저장하지 않는다. 저장 중에는 같은 제출을 반복할 수 없게 하고, 성공한 재료는 현재 정렬 규칙에 따라 목록에 나타난다.

### 영수증으로 등록

1. 사용자가 사진을 선택한다. 업로드 전 크기와 파일 형식을 확인한다.
2. 서버는 로그인 사용자에게 속한 비공개 임시 파일로 저장한 뒤 분석을 요청한다.
3. AI가 구매 품목의 원문과 식재료 이름 후보를 구조화된 초안으로 반환한다. 품목명이 불분명하면 원문을 남기고 검토를 요구하며, 유통기한은 자동으로 채우지 않는다.
4. 사용자는 원본 사진을 보며 품목명을 수정하고, 불필요한 품목을 제외하며, 필요한 재료를 추가할 수 있다.
5. 사용자가 저장할 각 재료에 유통기한과 보관 장소를 직접 정한다. 선택한 재료 중 필수값이 빠지면 저장하지 않는다.
6. ‘확인한 재료 저장’을 눌렀을 때만 선택한 항목을 한 번에 등록한다. 초안을 시작할 때 지정한 냉장고 이름을 저장 전에 다시 표시하고, 현재도 편집할 권한이 있는지 확인한다. 검토 중 다른 냉장고로 이동했더라도 목적지가 조용히 바뀌지 않게 한다. 동일한 요청을 재전송해도 중복 생성하지 않는다.
7. 저장 후 원본 임시 사진을 삭제한다. 취소 시에도 삭제하며, 중단된 초안과 사진은 24시간 뒤 정리한다.

분석이 실패하거나 일부 품목을 읽지 못하면 기존 목록을 변경하지 않는다. 재시도하거나 직접 입력으로 계속할 수 있게 한다. 분석 중 화면을 벗어나도 재료가 자동 저장되지는 않는다. 다른 멤버에게는 저장된 식재료만 보이며 영수증 원본과 저장 전 초안은 업로드한 사용자만 볼 수 있다. 저장 전에 해당 냉장고에서 나가거나 내보내지면 등록을 차단하고 초안 취소와 사진 정리 절차를 적용한다.

### 요리 추천과 조리법

추천 요청에는 사용자가 선택한 냉장고에서 보유한 재료 이름과 남은 퍼센트, 기한 정보를 전달한다. 사용자가 해당 냉장고의 현재 멤버인지 서버에서 확인한다. 0%이거나 기한이 지난 묶음은 추천의 보유 재료에서 제외한다. 같은 이름의 여러 묶음은 재료 종류를 매칭할 때 합치되, 먼저 사용할 묶음은 이른 기한을 기준으로 안내한다. 초대받은 다른 냉장고나 개인 냉장고의 재료를 혼합하지 않는다.

다음 두 그룹을 함께 보여준다.

- 보유 재료로 만들어요: 필요한 재료 종류가 모두 있는 요리
- 조금만 더 사면 만들어요: 보유 재료를 활용하면서 추가 재료가 필요한 요리와 부족한 재료 목록

소금·식용유 같은 기본 재료도 사용자가 등록하지 않았다면 자동으로 보유했다고 가정하지 않는다. 계란과 달걀처럼 같은 재료를 뜻하는 표현은 별칭으로 매칭하되 화면에서는 사용자의 이름을 보존한다. AI가 제시한 부족 재료 분류는 서버에서 실제 목록과 다시 비교한다.

두 그룹 안에서는 기한이 임박한 재료를 활용하는 후보를 먼저 보여준다. 임박 재료 활용도와 추가 구매 수가 같은 경우의 세부 순위는 구현자가 결정한다. 실제 중량을 기록하지 않으므로 ‘보유 재료’는 종류 기준임을 표시하고, 조리법에서 필요한 양을 확인하도록 한다.

상세 화면에는 요리명, 전체 필요 재료와 양, 추가 구매할 재료, 예상 조리 시간과 기준 인분, 순서대로 나눈 조리법을 제공한다. 기존 레시피 데이터에 근거한 경우 출처를 표시하고, AI가 생성한 경우 생성된 조리법임을 구분한다. 제공되지 않은 출처 링크를 만들어 표시하지 않는다.

레시피 데이터원은 AI 공급자 평가와 함께 확정한다. 기존 레시피 검색 API와 생성형 API 어느 쪽도 연결할 수 있도록 결과의 출처 유형을 데이터에 포함한다. 초기 계획에는 후보 비교와 실제 연동 작업이 모두 포함되어야 한다. 추천 실패 시 보유 재료 목록은 그대로 유지하며, 재시도할 수 있다.

### PWA와 알림

웹앱 매니페스트와 서비스 워커를 구성한다. 사용자가 알림 설정을 명시적으로 눌렀을 때 지원 여부를 확인하고 권한을 요청한다. 지원하지 않거나 허용하지 않아도 식재료 관리와 추천을 이용할 수 있다. iPhone과 iPad의 설치·권한 조건은 지원 안내에서 설명한다.

알림 설정에서 사용자가 매일 받을 시간을 시·분 단위로 지정하고 알림을 켜거나 끈다. 초기값은 오전 9시이며 저장한 시간을 화면에도 표시한다. 시간과 알림 활성 여부는 개인 설정으로, 소유자를 포함한 다른 멤버가 변경할 수 없다.

서버의 정기 작업이 각 사용자가 지정한 시각에 현재 접근 가능한 모든 냉장고의 임박 재료를 조회한다. 기한이 오늘부터 3일 이내인 재료를 냉장고별로 구분하여 하루 한 번의 요약으로 묶고, 해당 재료가 없으면 보내지 않는다. 0%이거나 삭제된 재료는 제외한다. 같은 공유 재료라도 각 멤버는 자신의 설정 시각에 알림을 받는다. 발송 직전 멤버십을 다시 확인하여 나갔거나 내보내진 냉장고의 재료가 알림에 들어가지 않게 한다.

시간을 변경했을 때 오늘 아직 발송하지 않았고 새 시각이 남아 있으면 오늘부터 적용한다. 새 시각이 이미 지났거나 오늘 이미 발송했다면 다음 날부터 적용하고 설정 화면에 다음 발송 예정 시각을 표시한다. 예약 작업이 중복 실행되거나 시간을 바꿔도 같은 사용자에게 같은 현지 날짜의 요약을 다시 발송하지 않는다.

알림을 누르면 현재 접근 권한을 확인하고 관련 냉장고의 임박 목록으로 이동한다. 여러 냉장고가 포함된 요약이면 냉장고별 요약 목록을 먼저 보여준다. 더 이상 권한이 없는 항목은 표시하지 않는다.

푸시 구독은 로그인 사용자와 브라우저에 연결한다. 알림을 끄거나 해당 브라우저에서 로그아웃하면 해당 구독을 제거한다. 유효하지 않은 구독은 발송 결과를 받아 정리한다. 정기 작업을 실행할 서비스와 재시도 구현은 배포 환경에 맞춰 구현자가 선택한다.

## 듀 민트 디자인과 접근성

밝은 화면은 흰색과 옅은 민트, 어두운 화면은 짙은 그린과 밝은 민트를 사용한다. 카드·배경·추천 영역은 서로 다른 표면색으로 구분하며, 기한 임박은 살구 계열 배지와 남은 일수를 함께 사용한다. 글자·경계·입력칸·슬라이더·등록 창·알림·빈 화면에도 같은 테마 토큰을 적용한다.

테마를 바꿔도 현재 화면과 입력 중인 내용은 보존한다. 첫 화면에 잘못된 테마가 잠깐 나타나는 현상을 피하도록 초기 렌더링에 선호 테마를 반영한다. 브라우저의 시스템 테마 변경은 사용자가 시스템 설정을 따르는 경우에만 반영한다.

## 애플리케이션 구성

Next.js에서 화면과 서버 요청 처리를 담당한다. Supabase Auth는 사용자 인증, PostgreSQL은 영속 데이터, 비공개 Storage는 분석 전 사진을 담당한다. Next.js 서버는 인증된 사용자의 요청을 검증한 뒤 AI API를 호출한다. AI API 키나 서버 권한 키를 브라우저에 전달하지 않는다.

재료 데이터의 접근 권한은 현재 냉장고 멤버십으로 판단한다. 초대·멤버 관리는 소유자 역할을 추가로 검증한다. 알림 설정·푸시 구독·영수증 초안과 원본 파일은 사용자별 정책으로 보호한다. 사용자 ID는 클라이언트가 보내는 값을 신뢰하지 않고 검증한 세션에서 결정한다. 공유받지 않은 냉장고 ID나 다른 사용자의 초안·파일·구독 ID를 추측해도 조회·수정할 수 없어야 한다.

초대 토큰은 추측할 수 없는 값으로 만들고 서버에는 검증용 해시와 만료·사용·취소 상태를 저장한다. 초대 수락은 토큰 사용 처리와 멤버십 생성을 한 번에 처리하여 동시에 두 사람이 사용해도 한 사람만 참여하게 한다. 실시간 변경 수신과 추천 결과, 서버 캐시도 냉장고 권한을 기준으로 분리한다.

| 데이터 | 핵심 필드 |

유통기한은 시각이 없는 날짜로 저장한다. 임박 여부는 사용자의 시간대에서 계산하여 자정 부근의 날짜 차이를 피한다. 재료 수정·삭제는 읽었던 버전과 현재 버전을 비교하는 방식으로 충돌을 감지한다. 버전이 다르면 서버의 최신 값을 다시 읽고 변경 내용을 사용자에게 알려주며, 실패를 성공으로 표시하지 않는다. 원자적 버전 검사와 실시간 반영의 구체적인 구현은 구현자가 결정한다.

### AI 경계

이미지 분석 입력은 검증한 사진과 분석 지시이고, 출력은 품목별 원문·재료 이름 후보·검토 필요 여부다. 유통기한은 이 결과로 저장하지 않는다.

추천 입력은 보유 재료 종류와 각 묶음의 남은 양·기한이다. 출력은 레시피별 이름, 전체 재료 목록과 양, 조리 시간·인분, 단계별 조리법, 출처 유형과 출처 정보다. 출력은 서버에서 구조를 검증한 뒤 부족 재료와 활용할 임박 재료를 계산한다. 모델이 응답하지 않거나 형식이 맞지 않으면 재료 데이터를 바꾸지 않고 오류를 전달한다.

제공사별 호출 방식은 별도 모듈로 감싼다. 입력 계약과 화면이 특정 모델의 응답 형식에 직접 결합되지 않게 한다. 공급자 평가에는 한국 영수증의 품목 누락·오인식, 식재료 이름 정리, 조리법의 재료와 단계 일치, 응답시간과 호출 비용을 포함한다. 실사용자의 데이터나 결제된 API 호출이 필요하면 실제 연동 단계에서 사용 환경을 확인한다.

## 첫 구현 범위와 제외 범위

첫 구현에는 인증, 본인 및 공유 냉장고의 영속 데이터, 초대·참여·멤버 관리·나가기, 공동 재료 편집과 변경 반영, 직접 입력과 영수증 확인 후 등록, 목록 필터·검색·수정·남은 양·삭제, 두 종류의 요리 추천과 조리법, 듀 민트 라이트·다크, PWA 설치, 알림 시간 설정과 지원 환경의 푸시 알림을 포함한다.

실제 AI 공급자 연결과 푸시 발송 설정이 끝나지 않은 상태는 개발 중 상태다. 예시 결과로 화면만 동작하는 것을 서비스 완성으로 취급하지 않는다.

바코드 인식, 식재료 자체 사진 인식, 중량·정확한 인분 계산, 구매·배송 연결, 결제와 구독 상품, 커뮤니티, 영양 관리, 레시피 즐겨찾기, 네이티브 앱, 오프라인 변경 동기화는 첫 범위에 포함하지 않는다. 냉장고 소유권 이전·냉장고 자체 삭제·보기 전용 초대·자동 초대 이메일 발송도 첫 범위에서 제외한다. 알레르기·식단 제한에 맞춘 개인화 필터는 별도 요구가 확인되기 전에는 추가하지 않는다.

## 완료를 확인할 기준

1. 멤버십이 없는 두 계정으로 냉장고·재료·사진·초안·구독이 분리되는 것을 확인한다. 공유 냉장고의 멤버끼리는 재료만 공동 편집하고 다른 사람의 사진·초안·알림 설정에는 접근하지 못한다.
2. 새로고침과 재로그인 뒤에도 저장한 재료와 남은 양이 유지된다.
3. 같은 이름의 두 묶음을 서로 다른 기한과 남은 양으로 관리할 수 있다.
4. 영수증 분석만으로는 목록이 변경되지 않는다. 검토 화면에서 선택한 항목과 필수 날짜를 확인한 뒤에만 저장된다.
5. 저장 버튼의 연속 클릭이나 네트워크 재시도로 재료가 중복 생성되지 않는다.
6. 오늘, 3일 뒤, 4일 뒤, 기한 경과, 0% 상태가 정렬·표시·추천에 각각 맞게 반영된다.
7. 부족 재료를 서버에서 계산하고, 임박 재료를 활용하는 추천이 우선 노출된다. 추천 조회로 재료가 차감되지 않는다.
8. 실제 선택한 API로 영수증 추출과 요리 추천·조리법을 확인하고 실패·재시도 흐름도 확인한다.
9. 지원 기기에서 PWA 설치와 동의한 사용자의 푸시 수신·해제·알림 이동을 확인한다. 서로 다른 멤버가 지정한 시각에 각각 알림을 받고, 시간을 바꾸거나 정기 작업을 다시 실행해도 같은 날 중복 발송하지 않는다.
10. 모바일과 웹에서 라이트·다크·시스템 설정이 적용되고, 화면 전환·테마 전환·대화상자에서 글자와 조작 요소가 읽히고 겹치지 않는다.
11. 초대 수락 전에는 접근할 수 없고, 유효한 초대를 수락한 뒤 같은 식재료를 편집할 수 있다. 만료·취소·사용된 초대와 동시 수락, 중복 가입을 확인한다.
12. 멤버 나가기와 내보내기 뒤에는 실시간 수신·수정·추천·예약 알림·대기 중인 영수증 저장을 포함해 해당 냉장고 접근이 차단된다. 남아 있는 멤버의 재료 데이터는 유지된다.
13. 두 사람이 같은 재료를 동시에 수정하거나 한 사람이 삭제하면 오래된 요청으로 덮어쓰거나 삭제된 재료를 복원하지 않고 충돌을 안내한다.
14. 냉장고를 바꿔도 재료·추천·영수증 저장 목적지가 섞이지 않으며, 개인 목록을 공유 목록에 자동 병합하지 않는다.

## 구현자가 결정할 사항

DB 테이블과 파일의 실제 이름, Next.js 라우트의 구체적 구성, 폼과 서버 검증 라이브러리, 스타일 토큰의 코드 구성, 멤버십 기반 접근 정책과 원자적 저장·초대 수락, 실시간 변경 반영, 저장 충돌과 재시도의 구현, 테스트 도구, 배포와 정기 작업 서비스는 위 요구사항을 만족하는 범위에서 구현자가 결정한다.

AI 제공사·모델과 레시피 데이터원은 후보 평가 뒤 선택한다. 사용자에게 보여줄 추천 분류와 영수증 확인 절차는 제공사 선택과 관계없이 유지한다. 알림 시각은 이번 범위에 포함하며, 임박 기준 3일의 사용자별 변경 UI와 소셜 로그인, 추가 개인화 기능은 자동으로 확대하지 않는다.
